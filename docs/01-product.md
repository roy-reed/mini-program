# 产品需求与业务规则

## 1. 定位与角色

产品目标：让乐迷得到一份“乐队专门邀请我听新专辑”的可传播音乐邀请函。内容由乐队控制，个性化来自用户称呼与随机款式。

| 角色 | 需求 | 对应能力 |
| --- | --- | --- |
| 首次来访乐迷 | 快速拿到带自己名字的专属视频 | 填写称呼、抽取、生成、试听 |
| 回访乐迷 | 找回自己的邀请函 | 云端恢复、我的作品、再次保存 |
| 收到分享的朋友 | 先看朋友的邀请，再制作自己的 | 只读分享页、同款活动入口 |
| 乐队／运营 | 让首发素材与品牌表达一致 | 素材审核、组合配置、发布时间 |
| 管理员 | 处理失败、下架和成本异常 | 任务排查、暂停活动、权限和审计 |

## 2. 需求优先级

| 优先级 | 需求 | 范围 |
| --- | --- | --- |
| P0 | 称呼与身份 | 微信服务端身份、称呼填写、修改、隐私说明 |
| P0 | 活动与抽取 | 活动列表、活动状态、一次抽取、服务端随机、记录恢复 |
| P0 | 真实视频 | 预审母版、异步合成、姓名烧录、封面、失败重试 |
| P0 | 观看与传播 | 视频播放、保存相册、卡片分享、分享访问、撤销分享 |
| P0 | 管理与交付 | 基础后台、素材校验、任务查询、埋点、删除、部署和监控 |
| P1 | 体验增强 | 更丰富拆盒动画、主题皮肤、多语言、更多音乐平台入口 |
| P1 | 外部触达 | 公开 H5、可选海报和二维码，须单独评估身份与隐私 |
| P2 | 新玩法 | 多次抽取、收藏套系、成员款联动；另定规则与工作量 |

## 3. 称呼规则

| 项目 | 规则 |
| --- | --- |
| 文案 | “希望我们怎么称呼你？”；不要求实名或微信头像昵称 |
| 长度 | NFC 规范化并去掉首尾空白后 1–16 个 Unicode 字素簇；服务端与前端使用相同计数实现 |
| 字符 | 支持字体覆盖的中英文、数字、空格与常见姓名符号；拒绝换行、控制／双向格式字符、不可见字符；MVP 不支持 emoji |
| 排版 | 字数合规后仍做真实字体像素测量；最多两行，自动缩字号到下限；仍放不下则提示缩短，不默默截断 |
| 审核 | 保存前调用可用的文本安全能力；拒绝时允许修改，审核服务不可用时保持原称呼，不绕过检查 |
| 修改 | “我的”修改后影响以后新活动；已有邀请函保留生成时称呼快照 |
| 更新旧函 | 邀请函页点“用新名字更新”，再次确认；保留抽取款式，生成新版本；成功后替换当前版本 |
| 限流 | 默认每用户每天最多 3 次成功改名、每活动每天最多 2 次成功改名合成；服务端按 Asia/Shanghai 自然日计算 |

无差异改名不消耗次数。生成失败的重试不算新的改名合成；一次生成周期最多执行 3 次（首次加两次自动重试），用户点击重试不能重置该预算。预算耗尽或遇到永久错误后由运营排障并授权新的生成周期；过期文件合法重建也开始新周期。页面按服务端 `canRetry` 决定是否显示重试按钮。限额是防滥用的产品默认值，可在活动前调整，但不得靠客户端控制。

## 4. 盲盒规则

抽取单位为**已审核的款式版本**：音频片段＋背景＋固定文案／字体布局＋母版视频。举例：3 段副歌和 4 套背景最多可以形成 12 个组合，但只有运营批准且母版就绪的组合参与抽取。

| 项目 | 规则 |
| --- | --- |
| 抽取额度 | 每 `user_id + campaign_id` 一次；邀请函记录建立即锁定抽取结果 |
| 抽取时机 | 点击“拆开邀请”时请求服务端；动画只表现结果，不决定结果 |
| 随机方法 | 对已发布组合按正整数权重抽取；使用服务端安全随机整数，映射到累计权重区间 |
| 示例概率 | 12 款各权重 1：每款 1/12；概率指长期理论值，不保证短期出现次数 |
| 奖励语义 | 首版免费内容随机，无实物／金钱奖项，不使用虚假“中奖”文案 |
| 重入 | 已抽取则回到同一邀请函；渲染未完成则继续状态页 |
| 网络重试 | 返回同一抽取结果；不同幂等键也被用户／活动唯一约束保护 |
| 素材变动 | 发布版本不可原地修改；新增配置只影响之后抽取，历史记录保留版本快照 |
| 紧急下架 | 若单款素材权利撤回，受影响作品设为不可访问；运营处理，不能悄悄重抽成另一款 |

如业务决定开放重抽，需要一并调整次数、重复款规则、历史列表、成本预算和接口，不可只在前端加按钮。首版不把分享、拉人、广告观看设为生成或保存的前提。

## 5. 邀请函生命周期

将“抽取身份”和“视频文件版本”分开：邀请函固定一个款式，但可因改名产生多个视频版本。

| 情况 | 行为 |
| --- | --- |
| 首次抽取成功 | 创建邀请函、首个文字版本和持久渲染任务；返回处理中 |
| 重复点击／退出重进 | 查回同一个邀请函；继续原任务，不增加抽取 |
| 首次渲染失败 | 显示失败原因类别和“重试生成”，复用款式与称呼 |
| 改名重新合成 | 旧成功版本继续可用，新版本处理中；新成功后原子切换 `current_revision_id` |
| 改名合成失败 | 旧版本保持当前，新版可重试；不展示成功提示 |
| 视频文件过期 | 授权仍有效、数据未删除时，可按原快照重新合成同一版本，不重抽 |
| 活动暂停 | 不允许新增抽取，既有邀请函可看；已排队任务继续；需要全面停止时使用下架 |
| 活动结束 | 不再新增抽取；保留期内继续看、保存、更新原邀请函名字 |
| 活动下架／授权到期 | 停止新抽取、处理、重建和分享访问，媒体签名不再签发，并执行存储／CDN撤回 |
| 用户删除 | 撤销分享、终止相关任务、排队清理文件；取消已领取任务通过取消标记和写回检查实现 |

默认元数据与当前视频保存至活动结束后 90 天，或素材授权有效期结束，以较早者为准。上传素材、历史版本、删除等待期另见运营文档。期限必须在活动发布时展示；不承诺永久保存。

## 6. 传播与收听

邀请函页提供“分享邀请”和“保存视频”。前者让朋友打开小程序只读页，后者下载 MP4 后由用户自行发布到朋友圈等渠道。不会把小程序卡片分享当作直接发送视频文件，也不宣称可以自动发朋友圈。

默认分享卡片使用活动通用封面和标题，不带用户姓名。首次启用分享前提示“打开链接的人可以看到邀请函中的称呼”；用户明确开启后创建随机分享令牌。收到链接的人只能观看，不能改名、重抽或获取 OpenID。关闭分享后原链接失效；已经保存到他人设备的文件无法远程收回。

分享访问页不强迫访客先填写称呼；点“制作我的邀请函”后才进入自己的身份和称呼流程。这是对原图增加的传播入口，普通入口仍按原图执行。

“去听完整专辑”配置为可审核的官方小程序入口、自有已配置网页或复制平台名称／搜索词。具体平台能否直接跳转需逐个验证，不承诺在任意音乐 App 间直接唤起。

## 7. 统计定义

| 事件／指标 | 定义与来源 |
| --- | --- |
| `campaign_view` | 活动页有效展示；用会话去重 |
| `name_saved` | 服务端称呼保存成功；事件不包含称呼原文 |
| `draw_created` | 数据库首次插入唯一抽取记录，不是按钮点击次数 |
| `render_ready` | 当前版本上传、校验并写入成功 |
| `video_play` / `video_complete` | 播放开始／首轮播放到结尾；按邀请函版本＋会话去重 |
| `save_success` | 相册保存 API 返回成功；拒绝授权单独记录 |
| `share_intent` | 点击分享按钮或打开分享菜单，只代表意图 |
| `share_visit` | 合法分享令牌页面有效访问，过滤机器人和所有者自访 |
| 生成转化率 | 指定活动有效访问独立用户中，首次成功生成的独立用户占比 |
| 传播转化率 | 指定归因窗口内由分享进入的独立新用户中，成功生成者占比 |

事件只带内部伪匿名标识、活动／版本、时间和技术结果；不上传姓名、OpenID、签名 URL 或分享令牌到分析平台。分享归因默认 7 天、首次有效来源；与内容保留期限分别管理。
