# 素材规范与运营后台

## 1. 首批素材清单

| 素材 | 建议数量与规格 | 验收要点 |
| --- | --- | --- |
| 副歌片段 | 约 3 段，各 15–30 秒；优先交 WAV／48kHz／立体声母带 | 提供曲名、截取起止点和可用时限；无突然截断和明显爆音 |
| 背景 | 约 4 套；静态 1080×1920 PNG／高质量 JPG，或同画幅循环视频 | 有足够文字安全区；视频去掉原背景声或明确其混音方案 |
| 专辑视觉 | 封面、乐队标识、活动主视觉、分享封面 | 标注裁切规则和版权／品牌使用范围 |
| 字体与排版 | 授权字体文件、字体许可、长短姓名示例 | 服务端可再分发／部署范围已确认；无缺字、溢出 |
| 活动资料 | 乐队／专辑名、发行日、活动起止日、收听入口与联系方式 | 中文标点／名称统一；不含未公开发行信息的误发布 |

音频保持项目方批准的音质；建议对各片段做一致性响度检查，例如设计目标 -14 LUFS、真峰值不高于 -1 dBTP，但需音乐制作人确认，不能机械破坏原混音。数值为本项目建议，不是微信发布标准。

文件上传建议上限：音频 50 MB、静态图 15 MB、背景视频 200 MB；后台服务端检查实际媒体而非只信扩展名。原始文件放隔离区域，检查完成才进入可发布区。

## 2. 邀请函模板

画面默认竖版 9:16。静态背景可加缓慢运动和节拍动效，但首版优先采用已预制好的背景视频，减少不同手机效果差异。

| 元素 | 内容 | 排版规则 |
| --- | --- | --- |
| 上部 | 乐队标识／专辑名 | 在安全区内，与系统顶部界面留出距离 |
| 主文案 | “诚邀 {displayName} 收听” | 姓名是唯一用户输入变量；全部通过文字层绘制 |
| 次文案 | “{artistName} 全新专辑《{albumName}》” | 来自运营已审核配置 |
| 底部 | 曲目／发行信息／版权说明（适用时） | 不放个人 OpenID、内部任务号或长期签名地址 |
| 音轨 | 预先挑选的副歌 | 母版中固定，输出与预览使用同一音轨来源 |

720×1280 模板初始姓名框可设为 x=60、y=480、宽=600、高=180，48px 起、最小 30px、最多两行；这只是设计起点，须逐套背景评审。不要按“字符数×平均字宽”推测最终排版。

首版分享卡片使用通用活动视觉，邀请函视频中保留个人称呼。若后续增加二维码海报，二维码只放不透明分享入口，并验证尺寸、留白、实机识别和有效期；本期不把海报作为真实视频的替代交付。

## 3. 组合与概率配置

后台让运营选择“音频版本＋背景版本＋文字模板／字体版本”形成一款；每款必须生成母版并预览通过。音频 A 与背景 1 可用，不代表音频 A 与所有背景都自动可用。

权重只接受正整数。概率为某款权重除以该发布版本所有可抽款式的权重之和。若有特殊款，用户可以在规则说明中看到款式概率；不宣称限量，除非真的实现了库存与原子扣减。本期不实现库存。

配置见 [campaign.example.json](../specs/campaign.example.json)：3 段音频×4 套背景=12 个候选组合，权重均为 1，活动为 draft 且所有候选尚未审核。占位 objectKey 不对应真实云文件；发布必须验证真实对象、使用期限、母版、字体和预览审批。不能因为 JSON 结构正确就把样例当成已上线活动。

## 4. 管理后台页面

| 页面 | 核心能力 | 权限／限制 |
| --- | --- | --- |
| 活动列表与编辑 | 新建活动、编辑标题和日期、设置保留期、复制上次活动结构 | 复制不复制用户数据；素材授权需再次核对 |
| 素材库 | 上传、转码检查、预览、版本、使用范围、有效期 | 已被发布版本引用的资产不可直接覆盖或删除 |
| 款式与概率 | 组合配置、权重、生成母版、用测试名字预览 | 至少一个可用组合；正整数权重；布局与音轨检查 |
| 发布中心 | 草稿预览、发布摘要、定时开始、暂停／恢复、撤回 | 显示将生效的版本；撤回需说明原因并确认 |
| 运行看板 | 抽取／成片／访问数据、任务失败、队列长度、成本告警 | 不默认展示全部用户称呼，不导出 OpenID |

后台首版用表单＋固定模板即可。任意拖拽编辑器、多人实时协作和复杂审批流不在本期。

## 5. 发布与变更流程

1. **建立草稿**：录入专辑信息、活动时间、保存期限、收听入口，确定免费一次抽取规则。
2. **准备内容**：上传媒体、校验规格与使用期限，制作所有可抽组合的母版。
3. **预览验收**：用测试姓名生成成片，逐款检查文字、音轨、时长、封面和长名字。
4. **发布快照**：确认款式、权重和有效期后发布不可变版本；测试产物不进入正式用户数据。
5. **活动运行**：监控访问／失败／排队与成本；必要时暂停新增抽取；结束后按期限归档和清理。

活动运行中要替换视频或改变权重，创建新的发布版本并说明变更；已有邀请函保留原快照。若权利撤回，需要撤回相关作品和媒体，而不是仅从抽取池里移除。

## 6. 数据与素材保留

以下是首版建议策略，最终须与项目方的告知内容和素材授权一致。

| 数据 | 默认保留／删除行为 |
| --- | --- |
| 当前视频、封面和邀请函元数据 | 至活动结束后 90 天，或使用权到期，以先到者为准 |
| 旧称呼视频版本 | 新版成功后最多再保留 7 天用于短期故障恢复，旧分享立即撤销；到期清理旧文件及姓名快照 |
| 分享令牌 | 默认 30 天，不超过活动／权利保留期限；只保留哈希 |
| 原始素材与母版 | 存续至所有引用活动的需要结束且仍有使用权；未经确认不自动永久保存 |
| 运行与分析日志 | 原始去敏事件默认 30 天，汇总无身份指标默认 180 天；根据实际告知调整 |
| 用户删除 | 请求即停止访问；目标 24 小时内清理在线姓名、作品文件、分享和个人元数据；备份随轮换最多 30 天消退 |

个人帐号默认在无有效作品且连续 180 天未使用后清理，隐私说明需相应告知。删除失败须重试并进入运营看板；恢复数据库备份后重放删除日志，避免已删除用户重新出现。删除日志仅含必要内部标识与动作，不保留原称呼。

作品删除为“删除内容并保留同活动已抽取占位”，占位只含内部用户／活动与删除时间，至活动清理一并删除。完整账户删除后不保留可关联的防重抽标识，因此再次登录可以成为新用户；免费玩法接受该限制，不通过设备指纹弥补。

## 7. 微信发布准备

注册／确认小程序主体与管理员、获取 AppID，依据实际经营内容核实服务类目、认证、备案和所需证明；选择与业务相符的入口，不预设个人主体一定能通过。配置 request／downloadFile 等实际使用的合法域名、HTTPS；首版无 web-view，不配置其专属业务域名作为必要能力，禁止把开发期“不校验域名”开关当作生产方案。

结合实际收集的数据和使用的相册等能力填写用户隐私保护指引，提供删除方式；名称输入和相册操作的授权时机分别处理。把音乐、封面、背景、字体及导出分享的使用范围整理成项目方可确认的清单。

具体微信接口、当前类目和提审条件须在项目实际后台与真机验证；本次未承诺已经完成帐号开通、授权、备案、微信审核或音乐平台跳转接入。依据记录见 [官方来源与决策](07-evidence-decisions.md)。
