# 开发排期、预算与验收

## 1. 工作量与团队

建议 2 名研发负责小程序与后端／媒体管线，设计、测试和乐队运营按阶段加入。总工作量含设计与测试，不能简单把人日等同于自然天。以下是原创规划估算，不是供应商报价。

| 工作包 | 工作量 | 依赖／成果 |
| --- | --- | --- |
| 产品细化、视觉与模板 | 5–7 人日 | 确认业务规则、页面稿、模板安全区与测试素材 |
| 小程序端 | 11–14 人日 | 身份、称呼、活动、抽取、任务、我的、保存与分享 |
| API、数据库与任务一致性 | 11–14 人日 | 数据迁移、鉴权、事务、幂等、版本、删除、埋点 |
| 媒体渲染与对象存储 | 6–8 人日 | 母版预制、文字层、真实 MP4、租约、重试、校验 |
| 管理后台 | 5–6 人日 | 活动、素材、组合、发布、任务和数据表单 |
| 联调、真机、部署与验收 | 8–11 人日 | 核心回归、并发／媒体验证、监控、部署、回滚和交付 |
| **合计** | **46–60 人日** | 素材就绪条件下研发目标约 4–5 周 |

上述含基础一次 UI 评审和必要技术修正；大量原创动画、复杂后台、音乐重混、跨端 H5、付费机制与多轮品牌改稿需要重新估算。单人全栈预计 8–12 周；业务主体和素材准备的等待时间单独计算。

## 2. 里程碑

| 阶段 | 重点 | 可验收结果 |
| --- | --- | --- |

| 第 3 周 M2 | 完成媒体 Worker、改名版本、分享访客、管理后台与素材发布 | 运营可以发布一套测试活动；用户可保存、分享、撤销、改名更新 |

## 4. 成本模型

将“开发投入”“素材制作／使用”“平台与云资源”分开报价。研发预算可按 46–60 人日乘以团队实际人日成本；若内部测算暂用 **1,000 元／人日**，对应 **4.6–6.0 万元**，此数字只是算术示例，不是市场报价，也不包含素材、税费、认证与云资源。

COS 官方计费按存储、流量、请求等项目划分，不应只计算存储费用。具体地域、实例规格、折扣及 CDN 选型确定后，再使用当日价格计算器。官方依据见 [S4](07-evidence-decisions.md)。

容量估算统一用十进制单位；20 秒视频，视频 2 Mbps＋音频 0.128 Mbps：`20 × (2 + 0.128) ÷ 8 = 5.32 MB`，实际编码与容器开销会有差异。

| 场景（示例假设） | 新成片数 | 成片总量 | 每份平均两次完整传输时的流量 | 单次渲染 12 秒时的槽位时长 |
| --- | --- | --- | --- | --- |
| 小范围试发 | 1,000 | 5.32 GB | 10.64 GB | 3.33 小时 |
| 普通活动 | 10,000 | 53.2 GB | 106.4 GB | 33.33 小时 |
| 较大活动 | 100,000 | 532 GB | 1,064 GB | 333.33 小时 |

这里“两次传输”和“12 秒”均为预算假设，不是测得数据或性能保证。流量另加分享观看、用户重播、失败重下、封面和母版回源；容量另加原始素材、历史版本和备份。槽位时长不是 vCPU 小时：还需乘实际每槽位 CPU／内存配置，才对应计算资源计费。

`月费用 ≈ API 基础实例 + Worker 配置×运行时长 + 数据库／备份 + 平均 GB·月存储×单价 + 外网流量×单价 + 读写请求 + CDN／域名／日志等`。

使用 COS 直出与 CDN 分发的计费路径分别计算，避免把同一份下行重复算作 COS 外网和 CDN 下行；CDN 回源则按实际发生的回源流量单列。

## 5. 容量与性能目标

初始验收负载假设：100 个同时在线会话，其中新增生成稳定到达率不高于 0.2 个／秒；媒体流量由对象存储承担。该数值仅作为首版压测基线，项目方提供真实首发流量后必须重算。

若实测每条占用一个槽位 12 秒，单槽理论容量为 5 条／分钟；`所需槽位 ≥ ceil(到达率 × 平均处理秒数 ÷ 0.7)`。例如 0.2 条／秒需要至少 4 槽；2 条／秒需要至少 35 槽。CPU／内存与编码配置可能让并行扩容不线性，必须做实际负载验证。

| 指标 | 目标 | 验证方法 |
| --- | --- | --- |
| 抽取 API 延迟 | P95 ≤1 秒 | 生产相似配置，测入库请求；不包含首次微信登录网络延迟 |
| 生成完成时间 | 20 秒标准模板端到端 P95 ≤60 秒 | 在约定生成到达率下包含排队、编码、上传和校验 |
| 渲染稳定性 | 合法素材最终成功率 ≥99% | 固定样本集连续 500 次，单列人工注入故障 |
| 结果一致性 | 同用户同活动 100 个并发请求仍仅一条抽取 | 包含不同幂等键和多端请求 |
| 恢复能力 | Worker 被杀死后任务在租约／重试窗口内恢复 | 检查最终只有一个当前成功版本且无错误分享 |

若目标不满足，先优化母版／编码、减少生成峰值、扩容和排队提示；不能把“已排队”统计成“已生成”。

## 6. P0 验收矩阵

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 新用户从普通入口进入 | 完成称呼后才进入项目；不强求真实姓名／手机号 |
| A02 | 已有称呼用户重新打开／换手机 | 恢复同一帐号称呼与作品 |
| A03 | 空白、长名、emoji、控制字符、缺字 | 按规则反馈；无页面或成片溢出；不写未通过称呼 |
| A04 | 同时多次点击抽取／多个设备请求 | 只有一个持久抽取、一个首版任务与同一款式 |
| A05 | 提交成功但响应丢失 | 重试找回原结果，不重抽，不重复扣额度 |
| A06 | 抽取后关小程序，稍后回来 | 服务端继续生成，回来恢复任务或成片 |
| A07 | API 事务失败／数据库重启 | 不出现“有抽取无任务”的部分提交 |
| A08 | Worker 崩溃、租约超时、上传后失联 | 可恢复；过期 Worker 不能覆盖有效结果；孤立文件可清理 |
| A09 | 真实视频导出 | 在小程序外播放仍有正确姓名、背景和副歌，音画同步，无黑帧／截断 |
| A10 | 改名更新成功／失败／重复提交 | 款式不变；成功切换一次；失败保留旧版；旧分享按规则撤销 |
| A11 | 点击播放、切后台、再进入 | 不自动同时播放多条音轨；进度行为一致且可控制 |
| A12 | 保存权限首次允许／拒绝／之后恢复 | 相册结果正确；拒绝不循环弹窗；地址到期可刷新 |
| A13 | 分享给朋友后打开 | 只读显示约定版本；朋友创建的是自己的邀请函；不暴露身份字段 |
| A14 | 猜测他人邀请 id／无效或撤销令牌 | 无越权数据、视频和敏感状态泄露 |
| A15 | 活动暂停／结束／下架／授权到期 | 新抽取、旧视频和任务分别按状态规则控制 |
| A16 | 删除作品／账户与生成同时发生 | 清理生效；Worker 不能复活已删除作品；个人删除可追踪到完成 |
| A17 | 修改发布配置／删除被引用素材 | 历史抽取快照不变；破坏性操作被阻止或执行明确撤回流程 |
| A18 | 权重概率与发布校验 | 零权重、负数、空池、无母版不能发布；抽样统计与理论概率相容 |
| A19 | 埋点与运营数据 | 区分分享点击／实际访问；无姓名、OpenID、令牌进入日志 |
| A20 | 真机与网络 | 至少 iOS、Android 中低端机；测试弱网、断网、重连和低存储空间 |

概率验证采用固定模拟输入测试权重边界，加足量统计检验；不要求每 12 次恰好出现每款一次。测试计划中明确随机误差阈值，不写必然波动的脆弱断言。

## 7. 上线与回滚

1. **发布前**：主体／类目／备案／隐私与真实素材就绪；staging 真机回归，成本与首发负载确认。
2. **部署**：先备份，再执行向后兼容迁移；部署 API 和 Worker，检查健康／队列／存储权限，再发布后台和小程序体验版。
3. **提审与灰度**：提供可复现审核路径和测试活动；按平台结果修正。发布后先小范围真实生成，再开放正式流量。
4. **故障处置**：暂停新增抽取，保留已生成内容；回滚应用镜像和活动配置引用；数据库不盲目执行破坏性 down migration。
5. **发布后**：检查日志、失败、分享访问、费用、备份及删除任务；记录发布版本、负责人、时间和回滚位置。
