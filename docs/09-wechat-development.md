# 微信原生小程序开发与真机手册

本手册专门处理微信运行环境。页面正确显示只是起点，身份、域名、后台切换、权限、媒体文件和体验版都要分别验证。以下排障为预防性工程检查，尚不是本项目的实际运行记录。

## 1. 开发前的账号与环境

| 操作 | 负责人 | 必须获得的结果 |
| --- | --- | --- |
| 确认账号为“小程序”及实际主体 | 项目负责人 | 确定 AppID、管理员和需要的主体材料；不能拿公众号 AppID 混用 |
| 绑定开发者与体验成员 | 管理员 | 开发者能登录工具和预览，测试人员能扫描体验版 |
| 安装微信开发者工具稳定版 | 开发者 | 记录工具版本；开发、测试使用一致基础库基线 |
| 安装 Node、pnpm、Git、Docker | 开发者 | 版本与项目台账一致，`docker info` 能连接服务 |
| 建立测试后端与媒体地址 | 后端负责人 | 手机能访问的 HTTPS API／媒体域名与完整证书链 |

Windows 开发者工具运行在 Windows；后端可以在 WSL／Docker。先确认 Docker Desktop／引擎已启动，不能把 CLI 已安装当作服务可用。手机里的 `127.0.0.1` 是手机自己，不能连接电脑本地 API；真机阶段必须使用可达的测试服务和已配置域名。

没有真实 AppID 时，可以完成页面和纯函数开发，但微信身份、内容安全、分享和正式提审仍是未验证。不能把测试号或模拟 OpenID 混入生产流程。

## 2. 首次导入的准确顺序

1. 在仓库根安装锁定依赖，启动开发数据库，完成迁移；分别启动 API 和 Worker，检查健康状态。
2. 填写开发配置，执行 `pnpm build:mp:dev`，确认 `apps/miniprogram/dist/app.json` 和 JS/WXML/WXSS 已生成。
3. 开发者工具选择“导入项目”，目录选 `apps/miniprogram`，类型选择小程序，填写对应 AppID；编译根目录由 project.config.json 指向 dist。
4. 选择记录过的基础库，先看编译／Console／Network；必要时清缓存重编译。不要修改 dist 修问题，应修改 src 后重建。
5. 配置真机 HTTPS 测试环境，执行 `pnpm build:mp:staging`，重新编译并扫码预览；记录真机型号、系统、微信、基础库和 buildId。

基础库兼容基线固定为 3.0.0；若实际所需能力要求更高版本，在S01显式提高并重新记录，S00／S01 写入台账；不是“永远使用工具当前默认”。调用前用能力检测处理差异，不支持核心隐私能力时明确引导升级微信，不能静默跳过同意。

## 3. 原生页面与导航

| 项目 | 实现要求 | 常见错误 |
| --- | --- | --- |
| 页面注册 | 每个页面在 app.json 注册，路由与文件大小写一致 | Windows 忽略大小写，Linux 构建和上传失败 |
| tabBar | discover/me 用 `wx.switchTab`；普通详情页用 navigateTo／redirectTo | 给 switchTab URL 加 query 传参数；正确做法是受控 store 暂存再读取 |
| 启动来源 | entry 解析活动 id；share 页解析不透明 token | 把任何 query 当作可信用户 id 或直接拼跳转 URL |
| 状态更新 | 仅 setData 更新需要展示的字段 | 每次轮询把大对象、二进制或所有列表全量 setData |
| 事件处理 | WXML 绑定的是 Page／Component 暴露方法 | 复制 Vue/React 模板语法到 WXML |
| 异步保护 | onUnload 标记已销毁；响应写回检查页面与请求序号 | 慢请求覆盖更新后的名字或已经离开的页面 |

启动流程使用共享 `ensureSession()` 单飞 Promise：多个页面同时需要身份时只交换一次 code。会话成功后再 `/me`；用户称呼为空进入称呼页。分享页可先只读观看，点制作时才走本人的会话流程。

`onHide` 暂停轮询和播放；`onShow` 重新查询服务器状态；`onUnload` 清理计时器、监听和下载任务。关闭小程序不取消服务端渲染任务。无栈返回时跳到 discover，避免分享页从外部打开后返回异常。

## 4. 网络与会话实现

| 行为 | 精确约定 |
| --- | --- |
| 网络封装 | 使用 `wx.request`，不要直接移植浏览器 fetch；将 HTTP 非 2xx 与网络 fail 分开 |
| API 超时 | 初始 10 秒；渲染接口立即返回任务，不能把 HTTP 超时调到几分钟来等待视频 |
| 401 | 单飞重新登录一次；重放请求时保留同一幂等键；再次 401 则停止并提示 |
| GET 网络失败 | 最多自动重试一次并退避；页面可手动重试 |
| POST 响应不确定 | 不生成新幂等键；按原键重放或查询本人邀请函，避免二次抽取 |
| 429／503 | 按 Retry-After／retryAfterSeconds 等待；按钮显示可重试状态，不能无限循环 |
| 轮询 | 2 秒→3 秒→5 秒加抖动，直到终态或页面隐藏；返回前台立即查一次 |
| 身份缓存 | 按内部用户隔离、到期清理；OpenID 和微信 session_key 不传客户端 |

`wx.login` code 由服务端交换，不等于自有 accessToken；`wx.checkSession` 的微信会话结果也不能替代项目 API 令牌是否有效的判断。code 不记录、不重复使用；失效后重新获取。

## 5. 隐私、称呼和相册是不同层次

业务称呼同意记录、微信隐私接口授权、`scope.writePhotosAlbum` 与手机系统相册权限分别处理，任何一项成功都不意味着另外几项自动成功。

首版不申请头像、手机号、位置、通讯录或麦克风。使用普通 input 输入称呼，避免因为误用附带额外能力的组件扩大权限范围。拒绝个人信息处理时仍可查看隐私／关于说明和已被明确分享的公开内容。

固定实现集中 privacy service：App只注册一次onNeedPrivacyAuthorization，把待处理resolve交给当前可见页面的privacy-dialog。组件使用官方agreePrivacyAuthorization按钮；bindagreeprivacyauthorization回调后才resolve同意；拒绝、卸载或没有可见页面均resolve拒绝并清队列；多个请求合并显示但逐个完成回调。查询适用隐私设置并在用户保存动作中按需requirePrivacyAuthorize，不依赖“什么都不写就一定自动弹窗”的假设。不得用本地布尔值冒充微信授权，也不得在 onLoad 中反复弹窗。官方类型说明 `getPrivacySetting` 和 `requirePrivacyAuthorize` 是辅助能力，具体流程依据实际接口选择，不要求无差别调用。

称呼校验与服务端使用同一规范化规则和字素簇算法；不假设所有小程序 JS 环境都有 Intl.Segmenter。前端用于及时提示，后端审核和字体检测才是最终依据。

## 6. 视频播放和保存

播放使用原生 `<video>`。只在用户点击时有声播放；最终视频已内含副歌，不另启动一条背景音频。播放器在切后台／离页时暂停。结果页上的姓名必须与视频 revision 一致。

保存按钮状态严格按 `idle → downloading → saving → success/failed` 实现；下载进度是真实传输进度，不能用来表示后台渲染百分比。

1. 查询当前版本与 `canSave`，向 `/media?purpose=download` 获取未过期签名地址。
2. 处理适用的隐私流程；由用户点击触发下载和保存，下载前确认没有重复任务。
3. `wx.downloadFile` 成功回调后还检查 `statusCode===200`、临时路径及媒体类型；HTTP 403／404 不是下载成功。
4. 用临时本地文件路径调用 `wx.saveVideoToPhotosAlbum`，仅其 success 才记录 `save_success`。
5. 失败分类：签名过期刷新一次；小程序权限拒绝提供设置入口；系统权限拒绝提供系统设置说明；空间不足提示清理；结束后释放临时资源。

官方类型资料明确视频相册保存使用本地路径并支持 MP4。支持 MP4 容器不意味着任意编码都能播放，因此仍用 H.264＋AAC 并做 iOS／Android 真机检查。背景视频／弹窗覆盖使用原生组件层级验证，不能只按浏览器 z-index 推断。

## 7. 分享实现

所有者明确开启分享后，服务端创建绑定 revision 的令牌。客户端在显示可用分享按钮之前准备好 `sharePath` 和通用 `imageUrl`。使用原生 `button open-type="share"` 与 `onShareAppMessage` 返回标题、路径和封面；不要把异步生成令牌的希望寄托于用户刚点开的分享面板。

未开启分享的私有页禁用个性化分享，右上角菜单策略与按钮一致；可保留不带个人信息的通用活动分享。首版不实现 `onShareTimeline`，也不承诺将 MP4 直接转发到朋友圈。客户端分享回调／点击不是“朋友已收到”的证明。

分享页拿令牌读只读 DTO；缓存时不跨用户混用私人详情。朋友点“制作我的邀请函”只携带活动 id 和允许的来源标识，不能把朋友的称呼、邀请函 id 或 revision 复制成自己的所有权。

## 8. 开发、体验和正式环境

| 环境 | API／媒体 | 用户与素材 | 用途 |
| --- | --- | --- | --- |
| dev | 本地或专用测试域名 | 明确假用户／测试素材 | 单元和本地迭代；页面可标 DEV |
| staging | 真机可达 HTTPS 测试域名 | 真实微信身份、单独库／桶 | 完整真机和体验成员验证 |
| prod | 备案／证书／域名配置就绪的正式域名 | 已批准真实素材和正式数据 | 提审候选包与正式版本 |

**提审包应在上传前构建为 prod。** 体验版不必天然连接 staging；微信的 develop／trial／release 是运行形态，不等于项目后端环境。不能 `trial → 测试服务器、release → 正式服务器` 自动切换，否则审核看到的内容与上线内容不同。buildId／API_ORIGIN 在包内固定，审核和正式发布使用同一候选包。

AppID 只有一个时，仍须通过不同后端环境隔离数据库与媒体；两个 AppID 的 OpenID 不能当作同一用户。不得在前端自行拼 UnionID 映射。
