# 微信提审、上架与发布后手册

**上架终点是：正式版可访问，真实用户可完成生成、保存和分享，运行人员能监控与处理故障。** 编译、扫码预览、代码上传、设为体验版、审核通过、正式发布分别记录，不混用“上线”。

菜单名称随微信后台变化；以下给出功能入口和需要取得的结果，以实际账号显示为准。本文未代项目执行注册、实名、备案、审核或正式发布。

## 1. 发布责任与资料台账

| 工作项 | 谁负责 | 需要提供／确认 | 完成证据 |
| --- | --- | --- | --- |
| 主体、管理员、开发权限 | 项目负责人／管理员 | 实际经营主体、实名信息、开发者／体验成员 | 后台状态记录，敏感材料不入 git |
| 基本资料 | 产品／乐队运营 | 名称、简称、图标、简介、服务联系方式 | 名称与界面内容一致 |
| 服务类目与资质 | 主体负责人 | 按真实音乐内容和互动功能选择平台实际允许类目；核实需不需要额外证明 | 后台类目及资质审核结果 |
| 小程序备案 | 主体负责人 | 主体、负责人、服务和网络信息，按平台指引核验 | 备案状态／编号已确认 |
| 域名与 HTTPS | 技术负责人 | API、媒体、后台、自有页面等域名，证书和实际接入服务 | DNS／TLS／备案与域名配置检查记录 |
| 内容使用 | 乐队／权利负责人 | 音频片段、图片、字体、视频合成与导出分享的范围和期限 | 素材台账的确认记录 |
| 隐私与删除方式 | 产品＋技术 | 收集字段、用途、期限、接收方／处理方、权利入口和联系方式 | 后台隐私指引与页面实现一致 |
| 审核说明与测试 | 发布负责人 | 访问路径、关键操作、演示素材、测试条件 | 发布候选包能按说明走通 |

**三个概念分别确认：微信认证、服务类目／资质、小程序备案。** 域名的网站备案也不自动替代小程序备案。官方备案资料要求相应服务先完成备案；实际材料和主体可用类目以平台及属地要求为准，不把“乐队自己的音乐”自动推导为免核实资质。

本项目不是微信小游戏，不为“盲盒”一词选择小游戏工程或游戏类目；玩法是免费内容随机。类目按真实服务核实，不能为通过审核选不相符的类别。

## 2. 时间安排与早期阻塞

P00 即启动主体、类目、备案、域名与素材确认，不能等编码结束才检查。官方备案处理与平台审核各有流程，不能把研发 4–5 周解释为承诺同一天上架，也不采用未经核实的固定费用／加急期限。

若后台提示所选类目需要当前主体不具备的条件，先记录提示、核实真实业务和允许方案；不要通过隐藏功能、提交一个版本后偷偷换另一种业务来解决。账号／实名／签署环节交给有权限的负责人，技术团队继续独立开发项。

## 3. 微信后台与基础设施逐项配置

| 配置入口／对象 | 操作与检查 | 验收结果 |
| --- | --- | --- |
| 开发管理中的服务器域名功能 | 录入实际 request／downloadFile 等使用域名，检查 HTTPS、证书链和重定向目标 | 关闭“不校验合法域名”后真机仍正常 |
| 媒体存储 | 私有桶、短签名、Content-Type、Range／下载行为、缓存鉴权 | 成片可播放和保存，原始素材不可匿名列举 |
| 安全配置 | AppSecret 后端保存，服务端所需 IP 白名单／接口权限按实际账号配置 | 登录和文本检查在正式环境真实可用 |
| 用户隐私保护指引 | 依据实际代码声明并完成平台要求的状态流程 | 体验与正式候选包能触发和完成对应授权 |
| 收听入口 | 首版无web-view；已验证音乐小程序appId/path或展示搜索词，复制需用户点击 | 无法跳转有搜索词出口，不宣称接入未验证平台 |
| 名称、图标、简介、类目、备案 | 检查后台完整性、有效期和一致性 | 没有“未完善／待核验”而假设能提审 |

每次域名或存储切换重新跑真机下载和签名过期测试。不要把测试隧道、临时地址、个人电脑或开发期豁免作为正式依赖。

## 4. 从代码到体验版

1. 冻结本次范围，记录 git SHA，执行全部自动检查和 P0 回归；确认没有占位内容、mock、调试账号和未实现按钮。
2. 部署兼容当前与上一客户端的生产 API／Worker，完成迁移、备份和媒体发布校验；实际生成至少一条成片。
3. `pnpm build:mp:prod` 构建候选包，在微信开发者工具检查 AppID、生产域名、代码体积与编译结果。
4. 用有权限的开发者上传，填写递增版本号和准确变更说明；在公众平台版本管理功能确认这次构建对应的开发版本。
5. 将候选版本设为体验版本、配置体验成员，以真实微信扫描，按完整主流程复测，保存 buildId 对应证据。

体验二维码可用不等于所有用户已能访问。正式候选体验版使用已审核可展示素材和生产依赖，不使用仅管理员可见的数据路径，否则审核人员可能看不到内容。

## 5. 提审前的可复现体验

| 必须可体验的内容 | 如何准备 |
| --- | --- |
| 新用户填称呼、抽取与生成 | 提供持续可访问的真实演示活动，不依赖审核者已抽过或特殊账号 |
| 内容可见 | 至少一套已批准的真实副歌与背景，文字完整；不能全是“敬请期待” |
| 异步等待 | 生产 Worker 运行，排队有限；长等待提示与作品恢复正常 |
| 保存与分享 | 下载域名、授权、只读页面和用户自己的生成入口可用 |
| 修改、隐私、删除、客服 | “我的”内入口可操作，联系渠道真实有人处理 |

如果正式专辑活动尚未开始，提供明确标注、真实合法且对所有符合条件用户同样可访问的演示活动，审核说明其与首发活动的关系。不得识别审核人员后特供隐藏内容，不绕过既定时间／概率／权限规则。

## 6. 审核说明模板

下面是填写模板，正式提交前将所有方括号替换为真实信息；此文件本身不是已提交材料。

```text
版本：[版本号]；构建：[buildId]；联系人：[真实联系方式]
用途：为[乐队/专辑]提供免费、随机款式的专属音乐邀请函。
流程：首页填写喜欢的称呼 → 选择[演示/正式活动名称] → 拆开邀请 → 等待生成 → 播放/保存/分享。
规则：每位用户每个活动抽取一次；无付费抽取、实物或现金奖品；修改称呼不改变款式。
内容：音频、视觉和字体使用范围已由项目方确认，[按平台要求说明材料位置]。
隐私：使用称呼生成视频；个人身份由后端微信登录处理；相册仅在用户保存时使用；“我的”提供隐私与删除入口。
测试条件：[活动可用时间、预计等待时长、如需账号则通过平台安全渠道提供]。
收听入口：[具体能力与可用路径，未接入的平台不宣称直接唤起]。
本次变更：[准确列出新增/修复项]。
```

不要把 AppSecret、长期 API token、个人身份证件或后台管理员密码写进仓库／审核备注。平台确实要求测试账号时，提供最小权限测试账号并用指定安全渠道传递。

## 7. 提交与驳回处理

在版本管理对应候选版本提交审核，逐项确认页面路径、服务类目、隐私信息与补充材料。记录审核编号、版本、提交时间和负责人；等待期间保持后端、素材和活动可用。

| 反馈类别 | 定位与修复 | 再提审证据 |
| --- | --- | --- |
| 页面打不开／空白／无法生成 | 核对正式域名、证书、活动可见性、登录、Worker和错误 requestId | 同一候选环境真机全过程记录 |
| 隐私声明与功能不符 | 对照实际接口和字段补齐声明，修正用户触发／拒绝流程 | 说明哪项已调整及授权页面 |
| 类目或资质不匹配 | 由主体负责人按真实服务核实并补材料／调整合规范围 | 实际后台资质结果，不假设改文案足够 |
| 内容权利问题 | 核实具体音频／封面／字体并替换或补齐可用依据 | 对应资产版本和确认范围 |
| 诱导分享／误导玩法 | 去掉强制转发、虚假奖励或概率描述，完整保留免费生成路径 | 普通用户不分享也能完成 |
| 功能不完整／外链不可用 | 完成必要操作或移除无效入口，明确音乐平台实际支持方式 | 所有公开按钮可执行 |

先保存原始驳回信息，定位可复现原因，一次针对明确问题修改。代码有变化则重新构建并上传新候选版本；仅后台材料修改也记录关联版本，依据平台流程重新提交。不能只改备注而不修行为，也不承诺某种修改必然过审。

## 8. 审核通过、发布和回滚

审核通过后确认活动时间、资源容量、客服、成本阈值和回滚负责人。经授权在公众平台发布已通过审核的那一版；若后台支持且适用，使用灰度能力，否则用小范围流量入口控制首发规模。不得未经验证宣称当前账号一定具备某种灰度／回退按钮。

发布完成后用**非开发／非体验成员的普通微信用户**从真实入口检查：搜索／二维码可达、称呼、抽取、成片、相册和分享都正常。正式版有缓存和更新机制，保留旧 API 兼容，不要求所有用户瞬间换到新包。

故障回滚顺序：暂停新增抽取→保留可用旧成片→回滚服务镜像／活动配置引用→按微信后台实际提供的版本回退能力操作；若不支持回退，则提交修复版本并维持服务降级。数据库采用向前兼容修复，不直接删表回退。每一步记录负责人、时间、版本与影响范围。

## 9. 发布后的运行检查

| 时点 | 必查 |
| --- | --- |
| 发布后 15 分钟 | 真实登录、抽取、任务完成、媒体读取和分享访问；普通用户样本 |
| 发布后 1 小时 | 最老排队、错误率、授权拒绝、媒体失败和费用异常 |
| 发布后 24 小时 | 删除／到期任务、备份、使用指标、实际资源成本与预期差异 |
| 活动期间每天 | 素材期限、域名／证书、队列和成本告警、用户反馈 |
| 活动结束 | 停止新抽取、保留期告知与清理任务；下架／授权撤回按对应流程执行 |

这些是运营执行要求，本次不自动创建定时任务。最终归档发布记录、候选包清单、验收证据、支持联系方式与故障经验。只有发布记录中“正式版普通用户验证”完成，才将 P15 标为 DONE。
