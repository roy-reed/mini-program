# 开发与上架故障手册

以下是按本项目技术路线整理的**预防性排障项**，不是声称团队已经遇到过这些故障。真正遇到问题后按文末格式补充证据，保留可复用的开发与上架经验。

## 1. 开发环境与微信客户端

| 现象 | 先检查 | 修复方向 | 如何证明恢复 |
| --- | --- | --- | --- |
| 导入后找不到 app.json | IDE 导入目录、miniprogramRoot、dist 是否生成 | 导入 apps/miniprogram，执行构建，修正配置而非搬文件凑路径 | 清缓存重编译成功 |
| 工具可运行、真机请求失败 | localhost、合法域名、HTTPS证书、实际重定向地址 | 部署可达测试服务，配置实际域名；关闭开发豁免复测 | 手机真实请求有 requestId 且服务端收到 |
| 页面 TS 已改但效果不变 | 是否重建、IDE 是否指向旧输出、缓存与 buildId | 修改 src 后构建，核对dist时间与buildId，必要时清缓存 | 页面显示准确构建信息 |
| Node 模块／window 未定义 | 是否把服务端包或浏览器库带入小程序 | 将调用放后端或使用 wx 适配器；只共享纯类型／纯函数 | dist 无非法导入并真机执行 |
| 跳 tabBar 报错或参数丢失 | navigateTo/switchTab 用法和注册路径 | tabBar 使用 switchTab，临时参数通过受控状态传递 | 冷启动和分享入口均能导航 |
| 登录反复循环 | AppID 与后端 AppSecret、code重复、token刷新并发 | 统一身份配置；single-flight；限制401恢复一次 | 同会话多个请求只交换一次，过期恢复正常 |
| 后台回来重复播放／轮询 | onHide/onUnload 是否清理 | 暂停媒体与timer；onShow只恢复一次 | 连续切换十次仍一条轮询、一条音轨 |
| Windows能过、CI构建失败 | 文件大小写、路径分隔符、依赖锁、环境变量脚本 | 统一实际路径，用跨平台 Node 脚本处理构建 | Linux干净检出构建成功 |
| Docker连接失败 | 引擎是否启动、context、端口映射 | 先让 docker info 成功，再启动容器；不要无限重跑 compose | 数据库ready且宿主连接成功 |

## 2. 媒体、任务与业务一致性

| 现象 | 先检查 | 修复方向 | 如何证明恢复 |
| --- | --- | --- | --- |
| 页面有名字，下载视频没名字 | 个性化文字是否真的进入FFmpeg输出 | 服务端烧录文字层，核对revision和对象key | 外部播放器看到相同称呼 |
| 保存失败但下载提示成功 | HTTP状态、临时路径、相册／系统权限 | 检查statusCode与媒体类型，再分类权限错误 | 相册可找到能播放的MP4 |
| 视频没有声音或双重声音 | 流映射、母版音轨、前端是否另播音频 | 固定一条已批准音轨；停止重复播放器 | ffprobe和真机均确认音轨正确 |
| 中文方框／长名字溢出 | Worker字体、授权文件、塑形和像素测量 | 使用批准字体与相同排版；生成前拦截缺字 | 长短名样本画面清晰不截断 |
| 渲染永久处理中 | 任务租约、心跳、清理扫描、资源超时 | 回收失联任务；分类重试；保留原款式 | 杀Worker后可恢复且不重复创建邀请 |
| 多次点击抽到不同款式 | 唯一约束、事务、客户端随机、幂等键 | 服务端结果唯一；事务提交后才能揭晓 | 100并发只返回同一持久结果 |
| 改名后又变回旧名字 | pending指针、完成CAS、旧页面响应 | 完成时校验当前pending与租约；丢弃过期响应 | 两次交错请求不会回退新版本 |
| 删除后视频又出现 | Worker写回没有查取消／所有权状态 | 事务二次检查，删除与任务同一保护顺序 | 故障注入复现后不再复活 |
| 分享关闭后仍有一次可播放 | 已签名地址的剩余有效期和客户端缓存 | 停发签名，必要时删除对象／清CDN；解释已下载副本限制 | 新分享API访问失败，既有签名按期限失效 |
| CPU很满、排队不断增长 | 到达率、单条耗时、并发数和内存 | 先用真实模板压测，再调槽位／扩容／限新生成 | 等待时长回落且失败率不升 |

## 3. 体验版、审核与正式版

| 现象 | 先检查 | 修复方向 | 如何证明恢复 |
| --- | --- | --- | --- |
| 扫码别人打不开 | 是否体验版、是否体验成员、版本是否撤回 | 绑定实际体验成员；正式可见需完成发布 | 指定体验成员扫码成功 |
| 审核看不到活动或无法抽取 | 活动时间、可见性、权限、是否仅给测试账号 | 提供合法可复现演示活动，普通符合条件用户同样可见 | 按审核说明从空白用户走通 |
| 体验版好、正式版连错数据 | 是否按envVersion动态切后端 | 构建固定环境；审核／上线用同一候选包 | 核对两端buildId和API_ORIGIN一致 |
| 审核提示隐私不一致 | 实际接口与后台声明、拒绝路径 | 修改真实行为和指引，不能只加无效弹窗 | 真机允许／拒绝均符合声明 |
| 类目／资质被拒 | 后台明确反馈与真实服务 | 主体负责人补足条件或调整实际业务；不选虚假类目 | 后台审核状态真实变化 |
| 上传完成但用户搜不到 | 是否仅开发版／体验版／审核中／通过未发布 | 按版本状态完成剩余步骤，再检查正式入口 | 非体验成员可访问正式版 |
| 发布后仍看到旧UI | 微信版本缓存、更新管理器、旧后端兼容 | 提示可用更新；保持旧协议兼容；不清用户云端数据 | 新旧客户端均可完成核心流程 |
| 需要紧急回滚 | 版本回退能力、后端兼容、活动开关 | 先暂停新增；服务回滚；按后台实际能力回退或提修复 | 普通用户已有作品仍可用 |

## 4. 每次真实故障的记录模板

```text
编号／发生日期：
影响环境与版本：git SHA、buildId、设备／微信／基础库、API／Worker镜像
现象与可复现步骤：用户实际看到什么，最小触发条件
证据：去敏requestId、任务id、截图或日志位置（不含令牌／姓名原文）
根因：已证实的原因；未证实猜测单独列出
修复：具体代码／配置及提交
验证：实际命令、真机结果、是否补回归测试
影响与后续：影响范围、数据是否需修复、适用版本和剩余风险
```

只有已有证据的条目进入 `docs/incidents/` 真实经验库。遇到同类问题先检索既有记录，核对版本和条件后再复用修复，不盲目照搬过时操作。
