# 01 · 产品流程与交互

> 本文件说明「用户看到什么、点了会怎样」。实现细节见 `04`，时间轴见 `02`。

## 1. 页面与跳转

| 页面 | 路径 | 作用 | 怎么进入 |
| --- | --- | --- | --- |
| 登录 | `pages/login/index` | 同意协议、填称呼；也是所有入口的「分流页」 | 启动、转发卡片、「修改称呼」（`?edit=1`） |
| 抽取 | `pages/draw/index` | 小电视载体，抽取邀请函 | 登录完成后 `redirectTo` |
| 邀请函 | `pages/invitation/index` | 信封 + 循环播放 | 抽取后 `redirectTo`（`?autoOpen=1`）；已抽过的用户启动时直接进入 |
| 协议与隐私 | `pages/legal/index` | 用户协议、隐私保护指引、删除我的数据 | 登录页协议链接、邀请函页底部链接（`navigateTo`） |

- 登录 → 抽取 → 邀请函都用 `redirectTo`，用户不会“返回”到上一步。
- 「修改称呼」和「协议与隐私」用 `navigateTo`，返回后回到邀请函。

## 2. 入口分流规则（`core/route.ts` 的 `decideEntry`）

每次打开登录页、抽取页、邀请函页都先算一次，不满足条件就跳到该去的页面：

| 顺序 | 条件 | 去哪 |
| --- | --- | --- |
| 1 | 本机没有同意记录 | 登录页 · 协议步骤 |
| 2 | 微信提示需要重新同意隐私（`wx.getPrivacySetting` 返回 `needAuthorization: true`） | 登录页 · 协议步骤 |
| 3 | 没有称呼 | 登录页 · 称呼步骤 |
| 4 | 没有抽取记录 | 抽取页 |
| 5 | 抽到的组合已不在清单里（素材下线） | 抽取页，并提示“原来的邀请函款式已更新，请重新抽取” |
| 6 | 以上都不是 | 邀请函页 |

## 3. 登录页

```
┌──────────────────────────┐
│      （阳光色背景插画）     │
│         共享和弦           │
│   一封写给你的音乐邀请函     │
│                          │
│  ○ 我已阅读并同意《用户协议》│
│    和《隐私保护指引》       │
│  ┌──────────────────────┐ │
│  │       微信登录        │ │
│  └──────────────────────┘ │
└──────────────────────────┘
```

**协议步骤**
1. 勾选框**默认不勾**。未勾选时点「微信登录」：提示“请先阅读并勾选协议”，不进入下一步。
2. 勾选后，「微信登录」换成 `<button open-type="agreePrivacyAuthorization">`。用户点它 = 同意隐私授权；在 `bindagreeprivacyauthorization` 回调里记录同意时间（本机），进入称呼步骤。
3. 《用户协议》《隐私保护指引》点击后打开协议页对应标签。

**称呼步骤**
```
  邀请函上怎么称呼你？
  ┌──────────────────────┐
  │ 输入称呼，或使用微信昵称 │   ← <input type="nickname">
  └──────────────────────┘
  最多 10 个字，只保存在你的手机上
  （错误提示，红色）
  ┌──────────────────────┐
  │        下一步         │   ← form 提交
  └──────────────────────┘
```
1. 用户可以手动输入，也可以点键盘上方的微信昵称。
2. 微信会在输入框失焦时检查内容，不通过会清空内容并通过 `bindnicknamereview` 告知（`pass: false`）[^input]。
3. 点「下一步」：等最多 800ms 的微信检查结果 → 本地规则校验（`core/name.ts`）→ 保存 → 进入抽取页。
4. 本地规则：去掉首尾空格、多个空格合成一个；最多 10 个字；只允许中文、字母、数字、空格和「·」；不能包含保留词（共享和弦、官方、客服、管理员、微信、腾讯）。
5. **修改称呼**（`?edit=1`）：标题改为“修改称呼”，输入框预填旧称呼，按钮“保存”，保存后返回邀请函页，邀请函上的称呼立即更新，抽到的款式不变。

## 4. 抽取页

```
┌──────────────────────────┐
│    请抽取您的专属邀请函      │   ← 文字在电视外面
│                          │
│        \    /             │
│     ┌──────────────┐      │
│     │ ░░ 屏幕动画 ░░ │      │   ← 小电视（Demo 用 CSS 画）
│     │   点击抽取     │      │
│     └──────────────┘      │
│                          │
│  ┌──────────────────────┐ │
│  │       点击抽取        │ │
│  └──────────────────────┘ │
│          规则说明          │
└──────────────────────────┘
```
1. 小电视轻微上下浮动；屏幕里是流动的色块和扫描线（美术版换成手绘电视 + 循环小动画）。
2. 点小电视或按钮（只响应第一次）：
   - 0–300ms：电视放大到 1.15 倍并轻微抖动；
   - 300ms：抽取（画面、音乐各随机 1 个，结果立即保存到本机），`wx.vibrateShort({ type: 'light' })`；
   - 300–700ms：电视放大淡出 + 全屏粒子炸开和白光（参考炉石传说开包）；
   - 700ms：`redirectTo` 邀请函页（`autoOpen=1`）。
3. 「规则说明」：弹窗显示“免费参与，每人一份。画面 N 款、音乐 M 首随机组合，每种组合的机会相同。不涉及任何付费、奖励或兑换。”（N、M 从清单计算）。
4. 已抽过的用户进入抽取页会被分流到邀请函页，不能重复抽。

## 5. 邀请函页

```
┌──────────────────────────┐
│   【专辑名】 · 2026.11 发行  │   ← 没有标题图时显示
│ ┌──────────────────────┐ │
│ │                      │ │
│ │   画面（视频循环）     │ │   ← 3:4 播放区
│ │                      │ │
│ │   诚邀 {称呼} 收听     │ │   ← 称呼叠在画面上
│ └──────────────────────┘ │
│ ╲______ 信封封皮 ______╱   │   ← 轻触封皮收起
│     轻触封皮收起            │
│   画面含 AI 生成内容        │
│   修改称呼 · 协议与隐私     │
└──────────────────────────┘
```

**信封状态**

| 状态 | 画面 | 点击 |
| --- | --- | --- |
| 收起 `closed` | 信封正面写“致 {称呼}”，下方提示“轻触信封，打开邀请函” | 点信封 → 打开中 |
| 打开中 `opening`（900ms） | 封口翻开，信纸（先显示封面图）升起并放大到播放区大小 | 忽略 |
| 已打开 `open` | 播放区挂载 `<video>` 并开始播放；信封封皮留在播放区下方 | 点封皮 → 收起中 |
| 收起中 `closing`（900ms） | 先停止并卸载视频，信纸落回信封，封口合上 | 忽略 |

**播放规则**
1. 抽取后进入（`autoOpen=1`）自动打开；之后再进入时停在“收起”，等用户点。
2. 视频地址来自清单；`loop` 循环；不显示进度条和控制条；`object-fit: cover`。
3. 称呼透明度跟着时间轴：淡入 1s → 显示 → 淡出 1s → 静息隐藏（`02` §6）。
4. 首次加载或缓冲时显示封面图和“邀请函加载中…”；出错显示“加载失败，请检查网络后重试”和「重试」。
5. 切到后台或锁屏时暂停；回来后如果信封还开着就继续播放。
6. 收起后再打开，从头播放。
7. 画面含 AI 生成内容时，播放区下方显示“画面含 AI 生成内容”（视频右下角也有合成进去的角标，见 `03` §4）。

## 6. 协议与隐私页

- 两个标签：用户协议、隐私保护指引（内容来自 `core/legal.ts`，源文本 `templates/legal-demo.md`）。
- 按钮「查看微信隐私保护指引」：`wx.openPrivacyContract()`，打开后台填写的隐私保护指引。
- 按钮「删除我的数据」：确认后清除本机的同意记录、称呼和抽取记录，回到登录页（协议默认不勾）。

## 7. 转发

- 登录、抽取、邀请函页右上角“···”可转发；协议页不能转发（图标灰色）。
- 转发标题“共享和弦 · 专属音乐邀请函”，图片 `assets/share.png`（5:4），打开后进入登录页。朋友看到的是自己的邀请函，不是转发人的。
- 不做“转发后得到××”之类的诱导。

## 8. 文案原则

- 所有文字在 `core/copy.ts`；改文案只改这里。
- 不用抽奖、开包、测试类词（`templates/forbidden-words.txt`）。可以用：抽取邀请函、打开邀请函、随机组合、专属邀请函、发给朋友。
- 说清楚“免费、每人一份、每种组合机会相同”，避免被当成抽奖。

## 9. 视觉方向

| 项目 | Demo（本周） | 美术版（之后） |
| --- | --- | --- |
| 整体 | 阳光米色底 + 暖橙主色，圆角卡片 | 实景 + 手绘，游乐园回忆主题，阳光色调 |
| 小电视 | CSS 画的复古电视，屏幕色块流动 | 手绘电视，屏幕播放静音小动画（C13） |
| 开包动效 | 放大 + 抖动 + 粒子 + 白光 | 更丰富的光效、碎片（C13） |
| 信封 | CSS 色块信封 | 手绘信封和信纸纹理（C14） |
| 称呼字体 | 系统字体 + 阴影 | 可选艺术字体（C15） |
| 大字标题 | 页面顶部系统字体 | 设计师出的标题图合成进画面（`03` §4） |

配色变量（`app.wxss`）：背景 `#FFF6E5`、纸面 `#FFFDF7`、正文 `#3B2A1A`、次要文字 `#7A6552`、主色 `#F2A541`、分隔线 `#EADBC3`、错误 `#C2410C`、播放区底色 `#000000`。
