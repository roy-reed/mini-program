# 02 · 邀请函时间轴与合成

> 对应 PPT 第 1、4 页（`ref/1026-时间轴.png`）。时间轴常量**只**写在 `miniprogram/core/timeline.ts`，渲染脚本和页面都 import 它。

## 1. 规则

PPT 第 4 页有三条轨道，从同一时刻开始：

| 轨道 | 内容 | 怎么实现 |
| --- | --- | --- |
| 音乐 | 本次抽到的一首音乐片段 | 合成进 MP4 |
| 视频 | 本次抽到的画面片段，首尾相接重复播放 | 合成进 MP4 |
| 文字 | 用户称呼（登录后就确定），浮在画面上，和画面是一个“组合体” | 播放时叠加，透明度跟着时间轴 |

一轮的顺序：
1. **淡入 1s**：画面、文字、音乐一起从 0 淡入。
2. **正常播放**：画面片段不断重复；文字常显；音乐播放。
3. **淡出 1s**：音乐最后 1 秒，画面、文字、音乐一起淡出。
4. **静息 3s**：黑屏、无声。PPT 原注：“音乐以淡出结束进入静息（无音），最后一个视频仍在继续播放，但被静息的黑屏覆盖”。
5. 静息结束后回到第 1 步，无限循环。

## 2. 计算公式

符号：`A` = 音乐片段时长，`L` = 画面片段时长（单位 ms）。

| 量 | 公式（默认 ceil 模式） |
| --- | --- |
| 实际音乐时长 `playMs` | `A` |
| 画面份数 `loopCopies` | `ceil(A / L)`（最后一份被截断，被淡出和静息盖住） |
| 一轮时长 `cycleMs` | `playMs + 3000` |
| 淡入段 | `[0, 1000)` |
| 正常段 | `[1000, playMs − 1000)` |
| 淡出段 | `[playMs − 1000, playMs)` |
| 静息段 | `[playMs, cycleMs)` |

限制：`10000 ≤ A ≤ 90000`；`500 ≤ L ≤ 10000`；都必须是整数毫秒。超出范围直接报错，不要自动修正。

## 3. 例子（也是单元测试用例）

| 音乐 A | 画面 L | 模式 | 份数 | playMs | cycleMs |
| --- | --- | --- | --- | --- | --- |
| 32400 | 4000 | ceil | 9 | 32400 | 35400 |
| 30000 | 3000 | ceil | 10 | 30000 | 33000 |
| 12000 | 7000 | ceil | 2 | 12000 | 15000 |
| 32400 | 4000 | floor | 8 | 32000 | 35000 |
| 12000 | 7000 | floor | 1 → 7000 < 10000 | 报错 | — |

## 4. 取整方式（Q01）

纪要摘要写“向下取整”，录音原话和 PPT 注释是“向上取整”（最后一个视频被黑屏覆盖）。**默认 ceil**，在 `assets-src/library.json` 的 `timeline.loopMode` 可改：

| 模式 | 做法 | 效果 |
| --- | --- | --- |
| `ceil`（默认） | 音乐完整播放，画面重复到盖满音乐，最后一份截断 | 和 PPT 一致 |
| `floor` | 音乐截短到“整数份画面”的长度（至少 1 份，且不少于 10 秒），在截短处淡出 | 每份画面都完整播完，但音乐会被截短 |

改模式后要重新运行 `render` 和 `manifest`（`03` §7）。

## 5. 合成：每个组合预先做成一个 MP4

为什么不在小程序里实时拼：GIF 解码 + 音频同步在低端机上容易卡、对不齐；预合成后小程序只播一个 MP4，最稳。代价是组合数 = 画面数 × 音乐数（Demo 建议不超过 6 × 6）。

每个组合的 MP4 本身就包含 **淡入 → 播放 → 淡出 → 3 秒黑屏静音**，小程序用 `<video loop>` 循环它，就等于 PPT 的“循环”。

### 5.1 FFmpeg 命令（由 `scripts/lib/ffmpeg-args.ts` 生成，下面是 A = 32.4s 的样子）

```bash
ffmpeg -y -hide_banner -loglevel error \
  -stream_loop -1 -i work/loops/door.mp4 \
  -i work/audios/track01.m4a \
  -i assets-src/overlays/title.png \
  -i assets-src/overlays/ai-label.png \
  -filter_complex "\
[0:v]trim=duration=32.400,setpts=PTS-STARTPTS,fps=30[base];\
[2:v]scale=720:960[title];\
[base][title]overlay=0:0[t1];\
[t1][3:v]overlay=W-w-24:H-h-24[t2];\
[t2]fade=t=in:st=0:d=1,fade=t=out:st=31.400:d=1,tpad=stop_mode=add:stop_duration=3:color=black,format=yuv420p[v];\
[1:a]aformat=sample_rates=44100:channel_layouts=stereo,atrim=duration=32.400,asetpts=PTS-STARTPTS,\
afade=t=in:st=0:d=1,afade=t=out:st=31.400:d=1,apad=pad_dur=3[a]" \
  -map "[v]" -map "[a]" -t 35.400 \
  -c:v libx264 -profile:v high -pix_fmt yuv420p -preset medium -crf 23 \
  -maxrate 1800k -bufsize 3600k -g 60 -r 30 \
  -c:a aac -b:a 128k -ar 44100 -ac 2 \
  -movflags +faststart \
  dist-assets/v1/combos/door__track01.mp4
```

要点：
- `-stream_loop -1` + `trim=duration=A`：画面无限重复后在音乐结束处截断，等于“向上取整，最后一份被盖住”。
- `setpts` 之后**必须**接 `fps=30`：否则帧率未知，`tpad` 不会补出 3 秒黑屏（已用 FFmpeg 7.0 实测：不加时视频只有 A 秒，音频却有 A+3 秒）。
- 标题图、AI 角标在淡入淡出**之前**叠加，所以会跟画面一起淡入淡出、在静息时被黑屏盖住。
- 没有标题图时去掉 `title` 相关两段，角标的输入序号顺延；画面不是 AI 生成时不加角标。
- 所有秒数从 `buildTimeline()` 的结果换算（保留 3 位小数），淡入淡出和静息时长来自 `timeline.ts` 的常量，不写死。
- `-movflags +faststart`：边下边播；`-maxrate 1800k`：35 秒约 7–8MB。
- 需要 FFmpeg 4.4 或更新版本（`tpad`、`apad=pad_dur`）。
- 标题图、角标必须带 **Alpha 通道**（导出为 32 位 RGBA PNG）：只靠“透明色”（tRNS）的 1 位 / 灰度 PNG，FFmpeg 读不到透明信息，叠加后整个画面变黑（已实测）。`assets check` 会检查像素格式。

## 6. 播放时叠加称呼

- 称呼不进 MP4（每人不同）。邀请函页在 `<video>` 上方放一个绝对定位的文字层（同层渲染，普通 view 即可覆盖在 video 上；C05 真机验证）。
- 文字内容：清单里的 `copy.inviteLine`（默认“诚邀 {name} 收听”）把 `{name}` 换成称呼。
- 位置：距播放区顶部 `layout.nameTopPct`（默认 70%），水平居中；颜色用当前画面的 `textColor`；字号由 `fitFontRpx()` 按宽度算（28–44rpx）。
- 透明度：

```ts
// 邀请函页 bindtimeupdate（示意）：约 250ms 触发一次
onTimeUpdate(e: WechatMiniprogram.VideoTimeUpdate) {
  const s = stateAt(this.timeline, e.detail.currentTime * 1000)
  const opacity = Math.round(s.opacity * 50) / 50 // 0.02 一档，减少 setData
  if (opacity !== this.data.nameOpacity) this.setData({ nameOpacity: opacity })
}
```

```css
.name { transition: opacity 250ms linear; }
```

- `<video loop>` 播到结尾自动回到 0，`currentTime` 变小，`stateAt` 自然回到淡入段，不需要额外处理。
- 允许误差：称呼与画面淡入淡出的时间差 ≤ 0.3 秒（真机 S10）。
- 视频还没开始播放（加载中）时，称呼透明度为 0。

## 7. 代码接口：`miniprogram/core/timeline.ts`（C01）

```ts
export const FADE_IN_MS = 1000
export const FADE_OUT_MS = 1000
export const REST_MS = 3000
export const MIN_AUDIO_MS = 10000
export const MAX_AUDIO_MS = 90000
export const MIN_LOOP_MS = 500
export const MAX_LOOP_MS = 10000

export type LoopMode = 'ceil' | 'floor'
export const DEFAULT_LOOP_MODE: LoopMode = 'ceil'

export type Phase = 'fadeIn' | 'main' | 'fadeOut' | 'rest'

export interface Segment {
  phase: Phase
  startMs: number // 含
  endMs: number // 不含
}

export interface Timeline {
  audioMs: number // 输入的音乐时长
  loopMs: number // 画面片段时长
  mode: LoopMode
  playMs: number // 实际音乐时长（ceil = audioMs；floor = 截短后）
  loopCopies: number
  loopTrackMs: number // loopCopies × loopMs
  cycleMs: number // playMs + REST_MS
  segments: Segment[] // 固定 4 段：fadeIn、main、fadeOut、rest，首尾相接
}

export interface TimelineInput {
  audioMs: number
  loopMs: number
  mode?: LoopMode // 默认 DEFAULT_LOOP_MODE
}

// 参数不合法（非整数、超范围、floor 截短后不足 10 秒）时抛 RangeError
export function buildTimeline(input: TimelineInput): Timeline

export interface PlayState {
  phase: Phase
  opacity: number // 0–1，画面和称呼的透明度
  volume: number // 0–1，与 opacity 相同（音乐的淡入淡出已合成进 MP4，这里用于展示和测试）
  cycleIndex: number // 第几轮，从 0 开始
  tInCycleMs: number // 本轮内的时间
}

// tMs < 0 按 0 处理；tMs 超过一轮按 cycleMs 取余
export function stateAt(tl: Timeline, tMs: number): PlayState
```

`stateAt` 的透明度：淡入段 `t / FADE_IN_MS`；正常段 1；淡出段 `(playMs − t) / FADE_OUT_MS`；静息段 0。
