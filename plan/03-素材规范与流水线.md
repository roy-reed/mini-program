# 03 · 素材规范与流水线

> 素材负责人（吴正元）看 §1–§6、§9；跑流水线的人看 §7–§8；Codex 实现 §6–§7（任务卡 C04）。

## 1. Demo 需要的素材

| 素材 | 数量 | 规格 | 放哪 | 必需 |
| --- | --- | --- | --- | --- |
| 画面（GIF / 短视频） | ≥ 2，建议 3 | §2 | `assets-src/videos/` | 是 |
| 音乐片段 | ≥ 2，建议 3 | §3 | `assets-src/audios/` | 是 |
| AI 角标图 `ai-label.png` | 1 | §4 | `assets-src/overlays/` | 有 AI 画面就必需 |
| 标题图 `title.png`（专辑名 + 发布时间艺术字） | 1 | §4 | `assets-src/overlays/` | 否（没有时页面顶部用系统字体显示） |
| 分享图 `share.png` | 1 | 500×400，≤ 100KB | `miniprogram/assets/` | 是（C10 先放占位图） |

## 2. 画面

### 2.1 技术要求

| 项目 | 要求 |
| --- | --- |
| 格式 | GIF、MP4、MOV、WebM 都可以；自带的声音会被去掉 |
| 时长 | 一个循环 0.5–10 秒（可用 `clip` 截取其中一段） |
| 尺寸 | 3:4 竖版，至少 720×960；比例不对会**居中裁切铺满**，边缘可能被裁掉 |
| 帧率 | ≥ 12 帧；统一转成 30 帧 |
| 循环 | 最后一帧能自然接回第一帧。做不到就设 `"pingpong": true`（正放后接倒放，适合秋千、摆动类动作） |
| 文件 | ≤ 20MB |

### 2.2 构图安全区（以 720×960 为准）

```
┌──────────────┐  0
│   标题区      │  8%–25%（用标题图时，避开主体）
│              │
│   主体区      │
│              │
│ ─ 称呼区 ─    │  62%–78%：保持干净、明暗均匀，称呼才看得清
│        [角标]│  右下角约 200×80：AI 角标
└──────────────┘  100%
```

### 2.3 风格

- 实景 + 手绘：实拍场景里加手绘线条元素；游乐园回忆主题；阳光、暖色调。
- 镜头固定不动（循环更自然）；每款一个小故事。
- 为每款画面定一个称呼颜色 `textColor`：深色画面用 `#FFFFFF`，浅色画面用 `#3B2A1A`（Q08）。

### 2.4 AI 生成与标识

- 用豆包、即梦等工具生成的画面，在 `library.json` 里设 `"aiGenerated": true`：流水线会在画面右下角合成 AI 角标，邀请函页也会显示“画面含 AI 生成内容”。
- 依据《人工智能生成合成内容标识办法》（2025-09-01 起施行）：发布 AI 生成内容要主动声明、使用标识，不得恶意删除、篡改标识[^cac]。转码会丢掉文件里的隐式标识，所以必须保留显式角标。
- 保存每个画面的生成记录（工具、日期、提示词、账号），和授权凭证放一起。

### 2.5 生成提示词（可直接改用）

**门洞穿梭**
> 竖版 3:4。实景照片风格的老游乐园砖墙，午后暖阳。一个手绘线条小人从画面右侧走进来，墙上用手绘线条画出一扇小门，小人开门走进去，门关上后消失，画面回到开始的样子。镜头固定不动，首尾画面一致可以无缝循环。画面下方三分之一保持简洁。

**台灯秋千**
> 竖版 3:4。实拍的木桌和一盏暖黄色台灯，台灯下挂着一架手绘线条的小秋千，秋千轻轻来回摆动。阳光色调，温暖怀旧。镜头固定，首尾画面一致可以循环。画面下方三分之一留白。

生成后检查：首尾帧是否接得上；有没有乱码文字、变形的手；画面里不要出现乐队以外的商标、真人肖像。

## 3. 音乐

| 项目 | 要求 |
| --- | --- |
| 格式 | MP3、WAV、M4A、FLAC |
| 时长 | 片段 10–90 秒。整首歌用 `clip` 截取，例如 `{ "start": 30, "duration": 32.4 }` |
| 起止点 | 选在乐句开头和结尾；结尾会自动做 1 秒淡出 |
| 音量 | 流水线自动标准化到 −16 LUFS，不同歌曲音量一致 |
| 版权 | 只用本专辑作品，并有权利人书面授权（§9） |

## 4. 叠加图

| 文件 | 尺寸 | 要求 |
| --- | --- | --- |
| `title.png` | 720×960，和画面同尺寸 | 透明背景，只在标题区（顶部 8%–25%）画专辑名和发布时间；会跟画面一起淡入淡出 |
| `ai-label.png` | 约 160×48 | 例如半透明深色圆角底 + 白字“AI 生成”；放在画面右下角，距边 24px |

两张图都必须**带 Alpha 通道**（导出为 32 位 RGBA PNG）。只靠“透明色”的 1 位 / 灰度 PNG，FFmpeg 读不到透明信息，叠加后整个画面会变黑（已实测）。`assets check` 会拦下来。

## 5. 分享图与图标

- `miniprogram/assets/share.png`：500×400（5:4），≤ 100KB；内容为小程序名称 + 主视觉，不含任何用户称呼。C10 先放一张纯色占位图，H04 换正式图。
- 小程序头像：144×144，和名称“共享和弦”一致；不含微信、腾讯标识；没有授权不用乐队 logo。

## 6. 素材登记表 `assets-src/library.json`

模板：`templates/library.example.json`。素材文件放在 `assets-src/` 下，路径都相对 `assets-src/`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 素材版本号（整数）。**每次换素材 +1**，决定 COS 目录 `v{version}` |
| `album.title` | 是 | 专辑名 |
| `album.releaseDate` | 是 | 发行时间的显示文字，如 `2026.11` |
| `copy.inviteLine` | 是 | 画面上的句子，必须含 `{name}`，默认“诚邀 {name} 收听” |
| `timeline.loopMode` | 否 | `ceil`（默认）或 `floor`，见 `02` §4 |
| `layout.nameTopPct` | 否 | 称呼距播放区顶部的比例，0.5–0.9，默认 0.7 |
| `layout.nameMaxRpx` / `nameMinRpx` | 否 | 称呼字号范围，默认 44 / 28 |
| `overlays.title` | 否 | 标题图路径；`null` = 不用 |
| `overlays.aiLabel` | 有 AI 画面时必填 | 角标图路径 |
| `allowUnequalWeights` | 否 | 默认 `false`：启用的画面权重必须相同、音乐权重也必须相同，因为规则说明写了“每种组合的机会相同”。要设不同权重，先改 `copy.ts` 的 `draw.rulesBody` |
| `videos[].id` | 是 | 小写字母、数字、短横线，如 `door`；不能有下划线（组合键用 `__` 连接） |
| `videos[].name` | 是 | 内部名称，不显示给用户 |
| `videos[].file` | 是 | 文件路径，如 `videos/door.gif` |
| `videos[].clip` | 否 | `{ "start": 秒, "duration": 秒 }`，截取一段作为循环片段 |
| `videos[].pingpong` | 否 | `true` = 正放后接倒放 |
| `videos[].textColor` | 是 | 称呼颜色 `#RRGGBB` |
| `videos[].aiGenerated` | 是 | 是否 AI 生成 |
| `videos[].weight` | 否 | 默认 1 |
| `videos[].enabled` | 否 | 默认 `true`；`false` = 下线（已抽到它的用户会被要求重新抽取） |
| `audios[]` | 是 | 字段 `id`、`name`、`file`、`clip`、`weight`、`enabled`，含义同上 |

## 7. 流水线命令（`scripts/assets.ts`，C04 实现）

准备：本机装 Node 22 和 FFmpeg 4.4+（macOS `brew install ffmpeg`；Windows `winget install Gyan.FFmpeg`），仓库根目录先 `npm install`。

| 命令 | 做什么 | 输出 |
| --- | --- | --- |
| `npm run assets -- check` | 检查登记表和文件：字段、id 规则、文件存在、时长范围、颜色格式、权重、PNG 尺寸和 Alpha、禁用词 | 终端表格；有错误就退出码 1 |
| `npm run assets -- normalize` | 画面 → 720×960、30 帧循环片段；音乐 → 44.1kHz 立体声 AAC + 音量标准化 | `work/loops/{id}.mp4`、`work/audios/{id}.m4a`、`work/probe.json` |
| `npm run assets -- render` | 所有「启用画面 × 启用音乐」合成 MP4 和封面（`02` §5）；输入没变的组合跳过 | `dist-assets/v{version}/combos/*.mp4`、`posters/*.jpg`、`report.json` |
| `npm run assets -- manifest --base <https 地址>` | 生成小程序清单 | `miniprogram/data/manifest.ts` |
| `npm run assets -- all --base <https 地址>` | 依次执行以上四步 | 同上 |
| `npm run assets -- sample --base <https 地址>` | 用 FFmpeg 生成 2 个测试画面 + 2 段测试音（不需要真实素材），跑完整流程，版本号固定为 0 | `work/sample/`、`dist-assets/v0/`、清单 |

`--base` 是 COS 上 `shared-chord` 目录的地址，例如 `https://sc-1250000000.cos.ap-guangzhou.myqcloud.com/shared-chord`。清单里的地址 = `{base}/v{version}/combos/{key}.mp4`。

**normalize 用的命令**（已实测）：

```bash
# 画面（有 clip 时在 -i 前加 -ss start -t duration；pingpong 时在 setsar=1 后接
#   split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1:a=0 ）
ffmpeg -y -hide_banner -loglevel error -i assets-src/videos/door.gif -an \
  -filter_complex "[0:v]fps=30,scale=720:960:force_original_aspect_ratio=increase,crop=720:960,setsar=1,format=yuv420p[v]" \
  -map "[v]" -c:v libx264 -preset medium -crf 18 -g 30 -bf 0 -movflags +faststart work/loops/door.mp4

# 音乐
ffmpeg -y -hide_banner -loglevel error -ss 30 -t 32.4 -i assets-src/audios/track01.mp3 -vn \
  -af "loudnorm=I=-16:TP=-1.5:LRA=11,aformat=sample_rates=44100:channel_layouts=stereo" \
  -c:a aac -b:a 192k work/audios/track01.m4a
```

时长测量：画面用帧数（`ffprobe -count_frames`）÷ 30，音乐用 `format=duration`，都换算成整数毫秒写进 `work/probe.json`。

**render**：参数由 `scripts/lib/ffmpeg-args.ts` 的纯函数生成（有单测），见 `02` §5。缓存：`work/cache.json` 记录每个组合的输入哈希（片段文件、音乐文件、叠加图、参数），都没变就跳过。

**sample 的测试素材**：

```bash
ffmpeg -f lavfi -i testsrc2=size=720x960:rate=30:duration=2 ...        # 画面 a
ffmpeg -f lavfi -i testsrc=size=720x960:rate=30:duration=3 ...         # 画面 b
ffmpeg -f lavfi -i sine=frequency=440:duration=12 ...                  # 音乐 a
ffmpeg -f lavfi -i sine=frequency=660:duration=15 ...                  # 音乐 b
# 角标：带 Alpha 的半透明方块（drawbox 要加 replace=1 才会写入透明度）
ffmpeg -f lavfi -i "color=c=black@0.0:s=160x48,format=rgba,drawbox=x=0:y=0:w=160:h=48:color=black@0.55:t=fill:replace=1" -frames:v 1 ai-label.png
```

sample 的登记表写到 `work/sample/library.json`；专辑名、画面名、音乐名都用英文（如 `Sample Album`、`Sample A`），不要用中文“示例”“测试”——它们在禁用词里，会让 `check:words` 失败。

## 8. 上传到 COS

1. 存储桶按 H03 创建（公有读、私有写）。目录约定：`shared-chord/v{version}/combos/`、`shared-chord/v{version}/posters/`。
2. 腾讯云控制台 → 对象存储 → 存储桶 → 文件列表 → 进入 `shared-chord/` → 「上传文件夹」→ 选本机 `dist-assets/v1`。
3. 用手机浏览器打开清单里任意一个 MP4 地址，能播放就说明公有读生效。
4. 已上传的版本目录**不要覆盖**（旧版本小程序还在用）；换素材就 +1 版本号。
5. 可选：给 `shared-chord/` 设置 `Cache-Control: max-age=31536000`（版本目录内容不变，可长期缓存）。
6. 费用：存储很少；主要是外网下行流量，一次完整播放约 7–8MB。在腾讯云设预算告警。

## 9. 换素材流程

1. 改 `assets-src/` 文件和 `library.json`（`version` +1）。
2. `npm run assets -- all --base <地址>` → 上传 `dist-assets/v{新版本}` → 提交 `library.json` 和 `manifest.ts`。
3. 更新 `版本记录.md`，小程序发新版本（清单打包在小程序里，必须发版才生效）。

## 10. 授权留档

| 素材 | 要留的凭证 |
| --- | --- |
| 音乐 | 权利人（乐队 / 厂牌）书面授权：可用于小程序内播放、剪辑片段 |
| 封面、插画（小红书购买，200 元商用授权） | 购买记录、授权说明截图；确认范围包含“小程序展示、视频合成、修改”（Q13） |
| AI 生成画面 | 生成平台、账号、日期、提示词、平台用户协议里关于商用的条款截图 |
| 字体（如用艺术字） | 商用授权证明 |

凭证放团队网盘，审核要求时能 10 分钟内拿出来。
