# 06 · 测试、验收与上架

## 1. 自动检查（Codex 每张卡都跑）

| 命令 | 覆盖 | 什么时候 |
| --- | --- | --- |
| `npm run typecheck` | 小程序代码 + 脚本 + 测试的类型 | 每张卡 |
| `npm test` | core 纯函数、流水线参数、禁用词检查、precheck；有 ffmpeg 时跑合成集成测试 | 每张卡 |
| `npm run check:words` | 禁用词、页面和组件里的硬编码中文 | 每张卡 |
| `npm run precheck` | 提审前的全部硬条件（`05` C11） | 上传前 |

## 2. 开发者工具检查（人，每张卡合并前）

1. 拉取 Codex 的分支 → 开发者工具「编译」→ 按任务卡「人工验收」逐条点。
2. 全流程前先「清缓存 → 全部清除」，模拟第一次打开。
3. 调试器 Console 无红字；「代码质量」面板无红项。
4. 视频相关的检查（C05、C09）以真机为准：模拟器的视频表现和真机不完全一样。

## 5. 上架步骤（H07）

1. `npm run precheck` 全部 ✓。
2. 开发者工具「上传」：版本号 = `APP_VERSION`（首版 0.1.0），备注“Demo 首版”。
3. 后台「管理 → 版本管理 → 开发版本」→ 选为体验版 → 体验成员扫码，至少复测 S01、S08–S10、S20、S22。
4. 「提交审核」：填写审核备注（`review/审核备注.md`）；Demo 不需要测试账号。
5. 等审核（通常 1–7 天）。被驳回：按 §8 修改 → 版本号第三位 +1 → 更新 `版本记录.md` → 重新上传提交。
6. 审核通过且小程序备案通过 → 发布（H09）。

## 7. 审核备注

模板：`templates/审核备注-Demo.md`（C00 复制到 `review/审核备注.md`）。填完【待填】后，把「版本描述」和「审核备注（完整版）」分别粘贴到「提交审核」页对应的输入框；备注栏有字数限制时改用「短版」（200 字以内）。要点：怎么体验（4 步）、随机组合的规则、“微信登录”只表示同意隐私指引、数据只存本机、AI 标识、素材授权。

## 8. 常见驳回与对策

| 驳回原因 | 可能的触发点 | 对策 |
| --- | --- | --- |
| 涉嫌抽奖 / 盲盒 / 随机奖励 | “抽取”“随机”字样 | 审核备注写明免费、无奖励、机会相同，规则说明随时可看；仍被驳回 → 只改 `copy.ts`：标题“打开你的专属邀请函”、按钮“打开”，去掉“抽取” |
| 功能不完整、测试性质 | 空页面、占位图、【待填】、样例素材 | `precheck`；换正式素材和分享图 |
| 强制授权 / 强制登录 | 首页就要求“微信登录” | 备注说明不读取微信账号、只填称呼；仍被驳回 → 登录页加“先看看”，用默认称呼“朋友”直接去抽取（一张小卡：login 页 + `copy.ts`） |
| 隐私：未声明或未经同意收集 | 后台没声明昵称；协议默认勾选 | H02；协议默认不勾选 |
| 自动播放 | 进入页面就出声 | 备注说明播放由用户点“抽取”或信封触发；仍有异议 → `AUTO_OPEN_AFTER_DRAW = false` |
| 类目不符 | 被认为是内容展示 | 备注强调“制作视频邀请函的工具”；参考旧包 `11` §4 的备选方案 |
| 名称、简介、图标不一致 | 简介写了没有的功能 | 按 H01 的简介 |
| 版权、AI 内容 | 没有标识或授权 | 角标 + 页面提示；按要求补交授权书 |
| 诱导分享 | “分享后得到…” | 禁用词扫描已拦截；转发不设任何奖励 |
